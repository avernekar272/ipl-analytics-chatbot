DATABASE: ipl_analytics_db

=== TABLE 1: deliveries_pq ===
Granularity: One row per ball bowled across all IPL matches.
Total rows: ~283,468 balls | ~1,193 matches | Seasons: 2007/08 through 2025

COLUMNS:
  match_id         BIGINT     Unique match identifier
  season           STRING     IPL season label e.g. "2024", "2023", "2007/08"
  start_date       STRING     Match date e.g. "2024-05-26"
  venue            STRING     Stadium name e.g. "Wankhede Stadium"
  innings          BIGINT     1 = first innings, 2 = second innings
  ball             DOUBLE     Over.delivery e.g. 0.1 = over 0 ball 1, 14.5 = over 14 ball 5
  batting_team     STRING     Team batting this ball
  bowling_team     STRING     Team bowling this ball
  striker          STRING     Batter facing the ball (use for batting stats)
  non_striker      STRING     Batter at non-striker end
  bowler           STRING     Bowler delivering the ball (use for bowling stats)
  runs_off_bat     BIGINT     Runs scored by the batter (excludes extras)
  extras           BIGINT     Total extras on this ball (wides + noballs + byes + legbyes + penalty)
  wides            BIGINT     Wide runs (0 if not a wide)
  noballs          BIGINT     No-ball runs (0 if not a no-ball)
  byes             BIGINT     Bye runs
  legbyes          BIGINT     Leg bye runs
  penalty          BIGINT     Penalty runs (rare)
  wicket_type      STRING     NULL if no wicket. Values: "caught", "bowled", "lbw", "run out",
                              "stumped", "caught and bowled", "hit wicket", "obstructing the field",
                              "retired hurt"
  player_dismissed STRING     NULL if no wicket. Name of dismissed batter.

IMPORTANT NULL RULES:
  wicket_type IS NULL     → no wicket on this ball (majority of rows ~95%)
  wicket_type IS NOT NULL → a wicket fell on this ball (~5% of rows)
  Always use COUNT(wicket_type) or SUM(CASE WHEN wicket_type IS NOT NULL THEN 1 ELSE 0 END) for wickets.
  NEVER use COUNT(*) to count wickets.

=== PLAYER NAME RESOLUTION — MANDATORY ===

CRITICAL PROBLEM: Cricsheet uses TWO naming formats across seasons:
  Pre-2020 seasons: initials format — "RG Sharma", "V Kohli", "JJ Bumrah"
  2020+ seasons:    full name format — "Rohit Sharma", "Virat Kohli", "Jasprit Bumrah"
  A single player may appear under BOTH formats in the same dataset.

MANDATORY SOLUTION — SELF-RESOLVING NAME CTE:
For EVERY query involving a specific player, the FIRST CTE must resolve all name
variants for that player in the dataset. Then JOIN to this CTE instead of filtering
by name in the main query. This guarantees cross-season accuracy.

BATTING SELF-RESOLVING TEMPLATE:
  WITH player_names AS (
      SELECT DISTINCT striker AS player_name
      FROM ipl_analytics_db.deliveries_pq
      WHERE LOWER(striker) LIKE '%surname%'
      AND batting_team = 'Exact Team Name'   -- ONLY add when surname is common (Sharma, Kumar, Singh, etc.)
  ),
  batting_stats AS (
      SELECT
          SUM(d.runs_off_bat) AS total_runs,
          COUNT(DISTINCT d.match_id) AS innings_played,
          COUNT(d.player_dismissed) AS times_dismissed,
          ROUND(SUM(d.runs_off_bat) * 1.0 / NULLIF(COUNT(d.player_dismissed), 0), 2) AS batting_average
      FROM ipl_analytics_db.deliveries_pq d
      JOIN player_names pn ON d.striker = pn.player_name
      WHERE [additional filters: season, venue, etc.]
  )
  SELECT total_runs, innings_played, times_dismissed, batting_average
  FROM batting_stats
  HAVING innings_played > 0

BOWLING SELF-RESOLVING TEMPLATE:
  WITH player_names AS (
      SELECT DISTINCT bowler AS player_name
      FROM ipl_analytics_db.deliveries_pq
      WHERE LOWER(bowler) LIKE '%surname%'
      -- AND bowling_team = 'Team'  -- only for common surnames
  ),
  bowling_stats AS (
      SELECT
          SUM(CASE WHEN d.wicket_type IS NOT NULL AND d.wicket_type != 'run out' THEN 1 ELSE 0 END) AS wickets,
          ROUND(SUM(d.runs_off_bat + d.wides + d.noballs) * 6.0 /
                NULLIF(SUM(CASE WHEN d.wides = 0 AND d.noballs = 0 THEN 1 ELSE 0 END), 0), 2) AS economy_rate,
          ROUND(SUM(d.runs_off_bat + d.wides + d.noballs) * 1.0 /
                NULLIF(SUM(CASE WHEN d.wicket_type IS NOT NULL AND d.wicket_type != 'run out' THEN 1 ELSE 0 END), 0), 2) AS bowling_average
      FROM ipl_analytics_db.deliveries_pq d
      JOIN player_names pn ON d.bowler = pn.player_name
      WHERE [additional filters: season, venue, etc.]
  )
  SELECT wickets, economy_rate, bowling_average FROM bowling_stats

=== CRICKET METRIC FORMULAS (SQL) ===

BATTING:
  Total runs by batter:
    SUM(runs_off_bat) WHERE striker = 'Player Name'

  Balls faced (legal deliveries only, excludes wides):
    SUM(CASE WHEN wides = 0 THEN 1 ELSE 0 END) WHERE striker = 'Player Name'

  Strike Rate = (Total Runs / Balls Faced) * 100:
    ROUND(SUM(runs_off_bat) * 100.0 / NULLIF(SUM(CASE WHEN wides = 0 THEN 1 ELSE 0 END), 0), 2)

  Batting Average = Total Runs / Times Dismissed:
    ROUND(SUM(runs_off_bat) * 1.0 / NULLIF(COUNT(player_dismissed), 0), 2)

  Fours:
    SUM(CASE WHEN runs_off_bat = 4 THEN 1 ELSE 0 END)

  Sixes:
    SUM(CASE WHEN runs_off_bat = 6 THEN 1 ELSE 0 END)

  Innings played (as batter):
    COUNT(DISTINCT match_id) WHERE striker = 'Player Name'

BOWLING:
  Wickets taken (credit goes to bowler, not for run-outs):
    SUM(CASE WHEN wicket_type IS NOT NULL AND wicket_type != 'run out' THEN 1 ELSE 0 END)
    WHERE bowler = 'Player Name'

  Balls bowled (legal deliveries — excludes wides and no-balls):
    SUM(CASE WHEN wides = 0 AND noballs = 0 THEN 1 ELSE 0 END) WHERE bowler = 'Player Name'

  Overs bowled = Balls bowled / 6 (Athena does integer division, use CAST):
    CAST(SUM(CASE WHEN wides = 0 AND noballs = 0 THEN 1 ELSE 0 END) AS DOUBLE) / 6

  Runs conceded (includes wides and no-balls, excludes byes/legbyes):
    SUM(runs_off_bat + wides + noballs) WHERE bowler = 'Player Name'

  Economy Rate = Runs Conceded / Overs Bowled:
    ROUND(SUM(runs_off_bat + wides + noballs) * 6.0 /
          NULLIF(SUM(CASE WHEN wides = 0 AND noballs = 0 THEN 1 ELSE 0 END), 0), 2)

  Bowling Average = Runs Conceded / Wickets:
    ROUND(SUM(runs_off_bat + wides + noballs) * 1.0 /
          NULLIF(SUM(CASE WHEN wicket_type IS NOT NULL AND wicket_type != 'run out' THEN 1 ELSE 0 END), 0), 2)

TEAM / MATCH:
  Total team score in an innings:
    SUM(runs_off_bat + extras) WHERE batting_team = 'Team' AND match_id = X AND innings = 1

  Highest team total in a season:
    SELECT match_id, batting_team, SUM(runs_off_bat + extras) AS total
    FROM deliveries_pq WHERE season = '2024'
    GROUP BY match_id, innings, batting_team
    ORDER BY total DESC LIMIT 1

  Number of matches played by a team:
    SELECT COUNT(DISTINCT match_id) FROM deliveries_pq WHERE batting_team = 'Team' OR bowling_team = 'Team'

=== INFERRING MATCH WINNERS — IMPORTANT ===

There is no explicit "winner" column, but match winners CAN and SHOULD be inferred
by comparing innings totals. Use this pattern for ALL win/result questions:

WINNER INFERENCE TEMPLATE:
  WITH innings_totals AS (
      SELECT
          match_id,
          innings,
          batting_team,
          SUM(runs_off_bat + extras) AS total_runs
      FROM ipl_analytics_db.deliveries_pq
      -- add any WHERE filters here (venue, season, team, etc.)
      GROUP BY match_id, innings, batting_team
  ),
  match_results AS (
      SELECT
          i1.match_id,
          i1.batting_team AS team1,
          i2.batting_team AS team2,
          i1.total_runs AS team1_runs,
          i2.total_runs AS team2_runs,
          CASE
              WHEN i2.total_runs > i1.total_runs THEN i2.batting_team
              ELSE i1.batting_team
          END AS winner
      FROM innings_totals i1
      JOIN innings_totals i2
          ON i1.match_id = i2.match_id
          AND i1.innings = 1
          AND i2.innings = 2
  )
  SELECT winner, COUNT(*) AS matches_won
  FROM match_results
  GROUP BY winner
  ORDER BY matches_won DESC
  LIMIT 10

HEAD-TO-HEAD WIN COUNT TEMPLATE (use when question asks about wins between two specific teams):
  WITH all_h2h_matches AS (
      SELECT DISTINCT match_id
      FROM ipl_analytics_db.deliveries_pq
      WHERE (batting_team = 'Team A' OR bowling_team = 'Team A')
        AND (batting_team = 'Team B' OR bowling_team = 'Team B')
  ),
  innings_totals AS (
      SELECT d.match_id, d.innings, d.batting_team,
             SUM(d.runs_off_bat + d.extras) AS total_runs
      FROM ipl_analytics_db.deliveries_pq d
      JOIN all_h2h_matches m ON d.match_id = m.match_id
      GROUP BY d.match_id, d.innings, d.batting_team
  ),
  match_winners AS (
      SELECT i1.match_id,
             CASE WHEN i2.total_runs > i1.total_runs THEN i2.batting_team
                  ELSE i1.batting_team END AS winner
      FROM innings_totals i1
      JOIN innings_totals i2
          ON i1.match_id = i2.match_id AND i1.innings = 1 AND i2.innings = 2
  )
  SELECT winner, COUNT(*) AS matches_won
  FROM match_winners
  GROUP BY winner
  ORDER BY matches_won DESC

WHEN TO USE WHICH PATTERN:
  - "Which team won the most matches at [venue]?" → General winner template with venue filter
  - "How many times did [team A] beat [team B]?" → HEAD-TO-HEAD template above
  - "Most successful team in IPL / in [season]?" → General winner template with season filter
  - Any question about wins, victories, titles, or team success

APPLYING FILTERS in the innings_totals CTE:
  - Filter by venue:  WHERE d.venue = 'Wankhede Stadium'
  - Filter by season: WHERE d.season = '2024'
  - Filter by team:   WHERE d.batting_team = 'Mumbai Indians' OR d.bowling_team = 'Mumbai Indians'
  - Combine filters with AND

=== ATHENA SQL RULES ===
  1. Always use ipl_analytics_db.deliveries_pq and ipl_analytics_db.matches_pq
  2. Use LIMIT clauses — return at most 20 rows unless user asks for all
  3. String comparisons are case-sensitive — use exact team/player names
  4. Use CAST(col AS VARCHAR) when concatenating numeric columns in strings
  5. For percentages: multiply by 100.0 (not 100) to avoid integer division
  6. Use NULLIF(denominator, 0) to prevent division by zero
  7. Do NOT use window functions unless essential — keep SQL simple
  8. Date filtering: use start_date LIKE '2024%' or season = '2024'
  9. Always alias columns with meaningful names (AS total_runs, AS wickets, etc.)
  10. Return only the columns needed to answer the question
  11. NEVER use SELECT * in any CTE or subquery — always list explicit column names.
      Reason: SELECT * in CTEs causes COLUMN_NOT_FOUND errors when downstream
      CTEs reference columns that were not explicitly selected.
  12. When using a filter CTE (e.g., to get match_ids for a venue/season),
      the subsequent aggregation CTE MUST JOIN back to deliveries_pq to access
      ball-level columns (runs_off_bat, wicket_type, etc.). Never assume those
      columns flow through a match-ID-only filter CTE.

  13. AGGREGATION QUERIES — ALWAYS ADD HAVING TO FILTER ZERO-RESULT GHOST ROWS:
      SUM() and COUNT() on an empty set return NULL/0 instead of no rows.
      This causes the app to receive a meaningless row and generate a confusing answer.
      For any player or team stat query, add HAVING after the final SELECT:
        HAVING COUNT(DISTINCT d.match_id) > 0   ← for batting/match count queries
        HAVING SUM(total_wickets) > 0            ← for bowling queries
      This ensures 0 rows are returned (not a ghost NULL row) when no data exists.

  14. CRITICAL — TABLE ALIAS QUALIFICATION IN JOINS:
      Whenever a query uses JOIN, EVERY column reference in SELECT, WHERE, GROUP BY,
      and ORDER BY clauses MUST be prefixed with the table alias.
      WRONG: COUNT(DISTINCT match_id)          → AMBIGUOUS_NAME error
      RIGHT: COUNT(DISTINCT d.match_id)        → unambiguous
      WRONG: WHERE striker = 'RG Sharma'       → AMBIGUOUS_NAME error
      RIGHT: WHERE d.striker = 'RG Sharma'     → unambiguous

      Correct full pattern for venue + player stats (Rohit Sharma at Wankhede example):
        WITH player_names AS (
            SELECT DISTINCT striker AS player_name
            FROM ipl_analytics_db.deliveries_pq
            WHERE LOWER(striker) LIKE '%sharma%'
            AND batting_team = 'Mumbai Indians'
        ),
        stats AS (
            SELECT
                SUM(d.runs_off_bat) AS total_runs,
                COUNT(DISTINCT d.match_id) AS innings_played,
                COUNT(d.player_dismissed) AS times_dismissed,
                ROUND(SUM(d.runs_off_bat) * 1.0 / NULLIF(COUNT(d.player_dismissed), 0), 2) AS batting_average
            FROM ipl_analytics_db.deliveries_pq d
            JOIN player_names pn ON d.striker = pn.player_name
            WHERE d.venue = 'Wankhede Stadium'
              AND d.season IN ('2021', '2022', '2023', '2024', '2025')
        )
        SELECT total_runs, innings_played, times_dismissed, batting_average
        FROM stats
        HAVING innings_played > 0
